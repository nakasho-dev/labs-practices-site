## この方法の使い方

{{% section %}}

### サンプルアジェンダとプロンプト

1. 「バックログからストーリーをピックアップ」または「誰かがアイデアを持っていた」のような開始イベントと、おそらく「顧客が新機能を使用した」となる最終イベントを提供します。

1. 全員に、本番環境への道のすべての「イベント」をブレインストーミングし、それぞれを付箋に書いてもらうように依頼します。

   人々がイベントを思いつくのに苦労している場合は、「コードレビューが完了した」、「本番ステージング環境にデプロイされた」、「...によって承認された」などの例のイベントを提供します。

   {{< callout >}}
   **ヒント:** 最終マップを一貫させるために、イベントは過去形である必要があります。
   {{< /callout >}}

1. 全員に、共有ボードの左(最も早い)から右(最も遅い)にすべてのイベントを配置してもらいます。この段階では、多くの重複があり、おそらく混乱するでしょう。

1. ボードを歩いて、重複を削除し、意見が異なる場合は順序を明確にします。不整合がある場合、プロセスのその部分に最も関与している人々が明確さを提供できるはずです。

   {{< callout >}}
   **ヒント:** 一部のタスクは多くの場合並行して発生しますが、それでも順序を定義する必要があります。チームが2つのことが同時に発生する可能性があると言う場合、順序は重要ではありませんが、それでも順序を設定し、誰かが異議を唱えるかどうかを確認してください。これにより、隠れた依存関係があるかどうかを見つけるのに役立ちます。
   {{< /callout >}}

   {{< callout >}}
   **ヒント:** チームメイトのペアにこのステップをリードするように依頼すると、全員がより関与していると感じるのに役立ちます。
   {{< /callout >}}

1. 各段階について、人々に関与しているシステムとツールの付箋(異なる色を使用)を作成してもらいます。マップ上の関連イベントの下に追加します。

1. 人々に各ステップに関与しているチームと人々の付箋(再度異なる色を使用)を作成してもらいます。マップ上の関連イベントの下に追加します。

1. 赤い付箋を使用して痛点をブレインストーミングし、マップに追加します。

1. グループと、プロセスの各部分を完了するのに通常どのくらいかかるかについて議論します。個々のステップではなく、2〜3ステップのグループに推定値を追加する方が簡単かもしれません。

   {{< callout >}}
   **ヒント:** タイミングを提供するのが難しい場合は、「Tシャツ」サイジングを試して、各セクションにSmall、Medium、またはLargeラベルを割り当てます。
   {{< /callout >}}

1. 空白の領域や未解決の質問がある場所がある場合は、答えを見つけるために人々にアクションを割り当てます。

1. フォローアップの時間を設定し、出力で何をするかを明確に述べます。

   状況に応じて、これは本番環境への道を改善し始めること、またはアプリケーションの最初のバージョンをリリースする方法を計画する際にリスクを軽減すること、またはその両方の混合である可能性があります。

1. セッション後、痛点がある領域や長い時間スケールがある場合は、それらを改善できるかどうか、またはできるだけ早くそれらに到達できるかどうかを確認します。言及されているすべてのツールとシステムにアクセスできることを確認し、会っていない関与しているチームまたは人々がいる場合は、彼らと連絡を取り、製品をプロセスを通じて移動するのを助けるために何が必要かを早期に見つけてください。

### ファシリテーターのメモとヒント

可能な参加者：

- Software Engineers
- Software Architects
- Product Manager
- Product Owner
- Security
- Compliance
- Delivery Manager
- Platform
- Security
- Compliance
- Designer
- アプリが本番環境に到達する前にヘルプまたは承認が必要な人

その他のメモ：

- 本番環境への道の痛点が特定されたら、本番環境への道を改善する方法を計画するためにソリューション優先順位付け演習でフォローアップします。
- 本番環境への道に沿ってリスクを取り除きたい場合は、このセッションで特定された痛みとリスクを軽減する方法を考え出すためのセッションを実行できます。
- アプリケーションを本番環境に到達させるために何が必要かを理解するための最も徹底的な方法は、マッピングしたプロセスを使用して「スチールスレッド」アプリケーションをデプロイしようとすることです。スチールスレッドは、基本的なセットアップと統合ポイントを持つアプリのバージョンですが、機能はありません。
