## この方法の使い方

### サンプルアジェンダとプロンプト

1. ワークショップの準備をします。

   **顧客にインタビュー**して、ジャーニー中のステップを見つけます。これらのステップをCustomer Actions行に沿って記録します。

   **ステークホルダー**とアクターをワークショップに**招待**します。アクターがデジタルサービスの場合は、専門家(SME)を招待します。

   {{% callout %}}
   ヒント: [カスタマージャーニーマップ](/practices/journey-map/)からステップを取得します
   {{% /callout %}}

2. ワークショップの実施（1〜2時間）。

   ![Service Blueprintの例](images/image1.png)

   ワークショップが始まる前に**カスタマージャーニーを記入**します

   最初の列から**開始**します。各アクターに5〜10分間、自分の行を記入してもらいます。

   ステップに**合意**してから、次のカスタマーアクションに移動します。

   最後に、メール、UI、テキスト、通知など、相互作用から生成される有形の証拠を**記録**します。物理的またはデジタルの証拠は、サービスによって消費または制御できる体験の一部です。

   {{% callout %}}
   ヒント: 証拠が提供するデータを調べて、ユーザーがすでに知っていることを理解することが役立ちます。
   {{% /callout %}}

3. 改善領域を分離することで、カスタマーエクスペリエンスを測定します。

   Experience: システムを壊す可能性のある**失敗点**を分離するか、**ワークフローを簡素化**します。

   Optimization: ベースライン測定を作成するために**時間**と**コスト**を記録します。

   Redundancies: **データ**を統合し、生成される**証拠**を合理化し、**痛点**を記録し、**標準**を導入します。

   {{% callout %}}
   ヒント: ビジネス成果に結びついたメトリックを使用します。ステップ数、ユーザーの不満など、将来比較できると思われるものを測定します。
   {{% /callout %}}

4. エクスペリエンスを改善し、サービスを最適化し、冗長性を減らす機会を見つけることで、既存のサービスを**反復**します。

5. 既存または将来のサービスに整列するために、ブループリントをチームと**共有**します。フィードバックは、ギャップを埋め、質問に答えるのに役立ちます。
